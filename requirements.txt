Project Name
PizzaHub — Pizza Ordering & Delivery Platform
Project Overview and Discussion
What is the project?
PizzaHub is a pizza ordering and delivery platform. Customers discover local pizza shops, browse their menus, and place food orders. Restaurants (vendors) create profiles, publish menu items (pizzas, sides, drinks), and manage incoming orders. Admins manage users, review published menu items, and monitor platform transactions.
Why should we develop it?
It is a complete, realistic, role-based web application. It tests your skills in authentication, authorization, database design, payment integration, and real-world business rules. Build PizzaHub as a functional pizza ordering platform, not just a collection of static pages.

How the system works
Role
	What they can do
	Customer
	Browse, search, and filter menu items; view item details; submit orders with a delivery date and address; track order status; cancel pending orders; use the Customer Dashboard
	Vendor (Restaurant)
	Create and manage the restaurant profile; add, update, and delete menu items; view customer orders and accept or reject them; manage the subscription plan; use the Vendor Dashboard
	Admin
	Manage registered users (vendors and customers); review and manage published menu items; view platform transactions; use the Admin Dashboard
	Vendors can upgrade to a Premium subscription to publish unlimited menu items and get promotional benefits: featured placement on the homepage and a "Premium" badge.

Payment System (Stripe Checkout)
Vendors must upgrade to Premium before publishing more than 3 active items.
1. Vendor clicks Upgrade to Premium
2. Backend creates a Stripe Checkout Session
3. Vendor is redirected to the Stripe Checkout page
4. Success leads to the Payment Success page
5. Cancel leads to the Payment Cancel page
After payment: show confirmation, save the transaction in the transactions collection, and update the subscription only after verified payment confirmation.

Payment security
* Do not trust the frontend success redirect to activate Premium
* Verify payment events with Stripe webhooks
* Keep Stripe secret keys on the server and do not expose sensitive payment information
* Prevent users from creating subscription sessions for other vendors
* Handle subscription cancellation and expiration properly
Profile Management
Vendors and Customers can update their name, profile image (optional), and other editable information, with success and error messages. Users must not be able to change their own role or subscription status through profile updates.
Backend security (JWT)
* Generate or obtain a JWT for authenticated users and store/send it securely
* Middleware to verify JWT tokens, and role-based middleware for Admin, Vendor, and Customer
* Protect all private API routes
* Verify resource ownership before any update or delete
* Validate request data on the server
* Never trust user IDs or roles sent by the client, and never rely only on frontend role checks
* Return 401 for unauthorized and 403 for forbidden requests
